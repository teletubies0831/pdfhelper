# 联网检索（DeepSeek Search / Fetch）

给 PDFPal 的两处功能提供实时网页检索：**知识库 → PDF 概览 → 相关论文**，以及聊天框的**联网**开关。
代码入口：`src/background/ai/deepseek-tools-client.ts`（HTTP）、`web-retrieval-service.ts`（编排）、
`src/viewer/features/assistant/web-retrieval-settings.ts`（设置表单）。

## 1. 接口事实（来自官方文档）

| 项 | 值 |
|---|---|
| 搜索 | `POST https://api.deepseek.com/v1/tools/search`，`{query, count(1–50，默认 10), ori_question?, need_content?}`，返回 `results[]`（`title`/`url`/`snippet`/`summary`/`content`/`date`/`authority`/`rerank_score`） |
| 抓取 | `POST https://api.deepseek.com/v1/tools/fetch`，`{url}`，返回 `{title, content}`（Markdown） |
| 鉴权 | 同一个 DeepSeek API Key（Bearer） |
| 计费 | 按**成功请求**计费，5 元 / 1000 次；`count` 与 `need_content` 不影响单价；**搜索无结果、抓取无正文、失败都不计费** |
| 限速 | 每个账号 Search / Fetch 各 5 QPS，独立计额 |
| 可重试 | 仅 408 / 429 / 5xx（重试一次）；401 / 402 / 403 / 404 是答案，不重试 |

三条直接决定了实现方式：

1. **`need_content: true` 让 Fetch 从主路径降级为兜底**。一次搜索就能带回每条候选的正文，成本仍是 0.005 元，
   所以默认路径是「1 次搜索」，只在候选正文为空且它进了前两名时才补 1 次 Fetch（上限可配，默认 1）。
2. **空结果免费**，因此「结果太少就换措辞再搜一次」是免费的策略，不需要为省钱牺牲召回。
3. **错误码语义不同**，于是 `WebRetrievalError` 带 `failure`/`retryable`，UI 文案按 `failure` 分派
   （401「密钥无效」/ 402「余额不足」/ 429「限流」/ 504「暂时不可用」），而不是把状态码丢给用户。

`localization` 字段**不使用**：它要求传入 IP 地址做结果本地化，没有必要把用户 IP 发出去。

## 2. 配置放在哪里

设置 → 模型与任务 →「联网检索」独立小节（不是「添加供应商」表单里）：tools 端点接受的不是模型，
也没有 `/models` 可以探测，塞进连接编辑器只会让「测试连接」那套流程无解；而且它属于 DeepSeek 这家服务，
与用户添加的哪条连接无关。
| 字段 | 默认 | 说明 |
|---|---|---|
| API 地址 | `https://api.deepseek.com/v1/tools` | **界面固定、只读**：tools 端点属于 DeepSeek，非官方地址没有意义。模型层仍允许空值（=未配置）以兼容旧记录 |
| API Key | 空 | 界面文案要求填写；留空时仍会回退到 DeepSeek 连接的密钥（`providerId === 'deepseek'` 的连接），只是不再写在界面上 |
| 候选条数 | 8 | 3–20，条数不影响单价 |
| 补抓正文上限 | 1 | 0–3，0 表示不补抓 |

「测试联网检索」按钮发一次固定查询的搜索（`count: 3`，不取正文），把结果条数、耗时和是否计费如实报出来——
这也是最初用来确认真实返回结构的手段。字段按下即存（与设置页其他偏好一致），否则表单说「已填」而按钮仍是灰的。

## 3. 三个入口

| 入口 | 触发 | 成本 |
|---|---|---|
| 设置里的「测试联网检索」 | 用户点击 | 1 次搜索（无结果不计费） |
| 知识库卡片上的「检索相关论文」 | 用户点击 | 1–2 次搜索 + 0–1 次抓取 ≈ 0.005–0.015 元 |
| 聊天框「联网」开关 | 提问时（开关为蓝） | 每轮 1 次搜索 ≈ 0.005 元 |

三者共用同一份配置与同一个客户端，但**互不联动**：聊天开着不影响概览按钮，关掉概览也不会关掉聊天。

### 3.1 「相关论文」：按需生成，入口在知识库卡片上

概览生成**不再**自动写相关论文——它要花一次检索加一次模型调用，而书籍、手册、合同的概览根本不需要它。

入口放在 **知识库 → PDF 卡片 →「查看概览」和「移出知识库」之间**，而不是概览对话框里。第一版把它做成了对话框
底部一个自带标题、说明和按钮的区块，结果在一个阅读界面里又长出了一份"文档"，还和旧版自动写入的「相关论文」
重复成两个标题——这是用户直接指出来的问题。现在：

- **卡片按钮**：`检索相关论文` / 已有结果时 `重新检索` / 检索中 `检索中…`。
  - 没配 DeepSeek 密钥 → `aria-disabled`（不是 `disabled`，否则 tooltip 不出现）+ 提示去哪儿配；
  - 还没有概览 → 同样不可用，提示「先生成 PDF 概览」——没有 `paper` 标题和主题就无从检索。
  - 结果通过与应用其余部分一致的后台任务浮框回报，含本次费用。
- **概览对话框**：只负责显示。拿到 `relatedLiteratureMarkdown` 就把它追加到概览正文**内部**（继承正文的内边距和
  排版），下面一行小字写来源、调用次数和时间。渲染时会**剥掉**旧版本存进 `overviewMarkdown` 里的「相关论文」
  小节（`stripLegacyRelatedSection`，只剥到下一个二级标题为止），但不动存储内容——手动编辑时仍能看到原文。

结果存在知识库文档记录的 `relatedLiteratureMarkdown` 里，**不**写进 `overviewMarkdown`：手动编辑概览会整段替换
markdown，混在一起会把用户付过费的章节删掉。

候选来自两路并行：DeepSeek 搜索（新工作、出版社/仓库页、引用页）与 OpenAlex（免费，作者/年份/DOI/被引数最可靠）。
排序是**确定性**的，不交给模型：先丢掉标题归一化后与本文相同的（自引）、丢掉 `rerank_score < 1.2` 的，
再按 `rerank_score` 排，`authority ≥ 3` 加 0.5、近三年加 0.3；OpenAlex 条目没有 rerank 分，用被引数折算。
取前 5 篇进提示词，前 2 篇附正文节选（≤2500 字），其余只给 `summary`（上游 600–800 字，正是给模型读的）。

提示词约束：链接必须逐字取自候选、不得拼接；没有正文的候选只能写标题/链接/年份；年份取候选给出的值。

降级链：搜索失败 → 用 OpenAlex 出章节并附一行说明；两路都空 → 「这次没有检索到可用的相关论文」。
任何情况下都不会拖垮概览本身。

### 3.2 聊天「联网」

一轮**一次**检索，结果作为上下文注入（`context.webSearchNotes`），模型不能自己反复翻页——延迟与成本都可控。
问题短于 12 字时在检索词后追加当前 PDF 标题（「它有什么局限？」这类问题否则搜不出东西）。
检索失败不阻塞回答：只在消息的 activity 行里留一条「联网检索失败，本轮回答未使用网页资料」。

## 4. 已知边界

- **没有缓存**。每次点击/每轮对话都是一次真实调用。理由是 0.005 元/次远小于一次模型调用的成本，而缓存会带来
  「为什么结果不是最新的」这类问题。如果以后需要，可以按论文标题加 TTL 缓存，落点显然是 `relatedLiteratureAt`。
- **搜索语法可用但暂未使用**：官方支持 `site:` / `"精确短语"` / `after:` / `lang:` 等操作符，目前第一轮是
  `"<论文标题>"`，第二轮是 `"<论文标题>" 相关工作 综述`。想提高精度时这里是第一个可调的地方。
- **相关论文只对 `paper` 类型生成**：概览头部有 `<!-- pdfpal-document-type: paper -->` 标记，其他类型直接返回
  「这不是学术论文」。
- 检索到的网页内容会随后续提示词发给你配置的模型服务商，隐私政策第 3 节已写明。
